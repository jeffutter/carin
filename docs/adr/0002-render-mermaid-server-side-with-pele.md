# Render Mermaid on the server with Pele in an embedded JS engine

Cairn renders Mermaid diagrams to SVG at submit time using Pele, a dependency-free JavaScript renderer, run inside a JS engine embedded in the one binary. Only the source is stored; the SVG is derived. A diagram that fails to parse is rejected at submit with Pele's error, so the Agent learns immediately.

We chose this over Mermaid.js in the browser (needs the large library served to every viewer, and gives no submit-time validation) and over `mmdc` (needs Chromium and Node on the host). Pele ran identically under Node and QuickJS with no DOM in a probe. The cost is an embedded JS engine in the binary, and a dependence on Pele's Mermaid compatibility, which is close to Mermaid 12.1.0 but not identical, so some valid Mermaid may be rejected. A spike confirmed that rquickjs builds in nix with only `clang` added. Engine start-up costs about 75 ms once; a small diagram renders in about 1 ms and a 300-edge flowchart in about 55 ms, so derived SVG is not cached. The engine runs with a memory limit, a stack limit and an interrupt handler (a 5 s deadline per render), and is discarded after any limit abort. The fallback, browser rendering with Pele, stays available but is not expected to be needed.

Status: implemented in `src/diagram.rs`. The engine starts lazily, once per thread, so commands that never render do not pay for it. Pele is pinned in `flake.nix` with `fetchzip` and exposed to the build as `PELE_JS`. If `PELE_JS` is unset, `build.rs` embeds a stub so non-nix `cargo build` still works; Mermaid then errors at runtime (see `docs/architecture.md`).
