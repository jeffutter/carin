# Store every Revision as a set of files in sqlite

Every Revision is a set of one or more files (path, media type, bytes) stored as BLOBs in sqlite, with file contents kept content-addressed (sha256) so Revisions that share a file share one blob. Markdown, image and diagram Revisions hold one file; an `html` Revision is a bundle with a required `index.html` plus assets. There is no files-on-disk store.

We chose this over a single-blob-per-Revision model (which cannot hold an HTML page with images without inlining them as data URIs) and over files on disk (which splits the data across the database and a directory, loses atomic writes and hard delete, and makes backup two steps). One database file also fits ADR 0001, where every subcommand opens the database directly. The cost is a database that grows with large bundles, bounded by fixed limits: 10 MiB per file, 25 MiB per Revision, 200 files per bundle. There is no Revision pruning and no total cap; deleting an Artifact removes its unshared blobs in the same transaction, and the database uses `auto_vacuum=FULL` so the file shrinks.
