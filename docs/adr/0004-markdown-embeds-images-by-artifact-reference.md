# Markdown embeds images by reference to other Artifacts

A markdown Artifact is a single file with no attached assets. It shows an image by pointing at another Artifact: `![alt](cairn:abc123)` for the latest Revision or `![alt](cairn:abc123@2)` for a pinned one. Only `image` and `diagram` Artifacts can be embedded. At submit, the server rejects a reference to a missing Artifact or Revision, and resolves each unpinned reference to the image's current Revision, recording it in a side table. The stored markdown text is never rewritten. Other image URLs (`http:`, `data:`, relative paths) are not fetched and show as alt text.

We chose this over giving markdown a bundle of attached files, which would add a second multi-file Kind with its own upload and edit rules, and over allowing remote or `data:` images, which would pull untrusted content into the review page. Embedded images get Kind handling, limits, storage and safe display from the existing Artifact machinery. The cost is that an agent uploads images before the markdown that uses them, and that image Artifacts show up in listings as Artifacts in their own right. Hard delete of an embedded image is allowed; markdown that references it shows a missing-image placeholder, so the Reviewer is never blocked from cleaning up.
